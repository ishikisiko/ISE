# 自主度评测：第一轮结论与第二轮固定修改范围

本计划在第一轮 80/80 条真实运行、80/80 条 v3-evidence 辅助评审结束后、第二轮产品修改前固定。第一轮结果保留于 `runtime/baseline/autonomy-20260908-measured/r1-analysis.json`；其源码快照与原始答案不覆盖。最终两轮报告另行交付。

## 第一轮结果

每组 20 条；质量为隐藏模式标签的模型辅助评分，不是真人验收。时延包含进程初始化；token 来自实际 HTTP 响应，超时或断连的用量只有下界。

| 题集 / 模式 | 完整交付 | 核心事实全对 | 辅助质量 /100 | 时延 P50/P95 秒 | 已知 token 均值 |
|---|---:|---:|---:|---:|---:|
| 事实 / guided | 18/20 | 18/20 | 62.50 | 32.64 / 113.04 | 5,991 |
| 事实 / autonomous | 20/20 | 19/20 | 75.00 | 7.52 / 62.17 | 1,769 |
| 开放 / guided | 13/20 | 不适用 | 62.50 | 227.86 / 660.28 | ≥32,198 |
| 开放 / autonomous | 13/20 | 不适用 | 61.88 | 103.69 / 187.47 | 7,176 |

不能据此声称 autonomous 在事实安全性上严格不劣：`final016` 的 autonomous 将 Google 成立日期答成 September 7, 1998，违背预先固定的 September 4 核心事实；guided 该题正确。错误检索片段支持了错误日期，因此综合评分被“有来源”补分，进一步说明核心正确性必须单列，不能只看总分。参考勘误与来源见[协议](protocol.md)。

开放题配对辅助分为 autonomous 4 胜、12 平、4 负，平均差 -0.625 分。两模式都只交付 13 条，尚无开放价值优势。autonomous 的实际 token 为 guided 已知下界的约 0.223 倍，但部分节省来自错误提前收尾，不能全部解释为效率提升。

## 已复现问题及原因

1. **工具协议被当作答案。** autonomous 的 `open004/007/010/013/020` 返回单竖线 DSML 或畸形变体，均被标记 `succeeded`，实际无答案。代码只识别双竖线 DSML；降级输出又未统一过滤工具协议，guided 的 `open005` 漏出了多个 `<{"action":"tool",...}>` 片段。
2. **usage 丢失。** `_act_shim` 重建 `AIMessage` 时丢弃元数据；所有 75 条有应用调用记录的运行均不能完整捕获 token。autonomous 的应用总 token 全为空，不能解释为零消耗。独立 HTTP 观察器使两轮仍可同口径比较。元数据也用于上下文估算校准，因此修复可能改变压缩触发时机，不只是报表变化。
3. **模型澄清归属未贯彻到循环内。** `open019` 的 “a system that deploys…” 被确定性分析器误判为未解析指代。autonomous 跳过了 loop 前短路，却在第一次检索后的 critic 被强制 `clarify`；`model_clarification=false`、未调用 `ask_user`。这不符合[澄清互斥契约](../../../openspec/changes/add-autonomy-policy/specs/model-initiated-clarification/spec.md)：是否发问应由模型决定。
4. **其余限制不混入本轮修复。** guided 在 `open002/007/013/018` 达到 660 秒硬截止；`final011/020` 没有交付答案；autonomous 的 `open017` 仅给研究计划，体现关闭语义 narration guard 后仍可能错误自收尾。guided 另有 15 条答案被评为完整但终态非成功（事实 6、开放 9）。这些现象分开报告，不用循环状态替代交付质量。

离线回归证据：`r1-regressions-v2.xml`，10 项中 7 项失败、3 项通过。通过项包括证据确实传到下一次 provider 请求、普通文字不误伤、guided 的循环内澄清行为；失败项是第二轮的明确修复目标。原始较早的 8 项测试记录另保留，不覆盖。

## 第二轮的一组产品修改

- 兼容实际出现的单 / 双竖线 DSML，仍只执行已启用且参数验证通过的工具；畸形协议反馈为未执行，不猜测工具名或参数。
- 在普通候选、降级合成及 best-effort 输出边界阻止未执行的工具协议泄漏；不执行合成阶段冒出的工具请求，不将工具语法当作有用回答。
- 保留 shim 响应的 usage / response metadata，使用原始调用 usage 校准上下文预算，即便之后发生内容归一化或拒绝。
- `clarification_owner=model` 时将分析器歧义作为提示交给模型，不由循环内 critic 强制发问；`system` 归属与 skill preflight 保持不变。

不修改题集、核心参考、v3 评审、provider / model、temperature、并发或时限；不向产品注入评测答案。默认仍为 guided。不会为了此次结果重新开启 autonomous 的 judge / narration guard / 强制合成，也不声称消除纯计划、自信错误或所有超时。

## 验证与预算决策

硬验证：上述 10 项回归全部通过；补测合成边界、旧 DSML 兼容和元数据校准；完整 pytest 与 OpenSpec 严格检查；实际 CLI / Flask 调用记录与独立 HTTP usage 对照。随后冻结第二轮源码，按反转模式调度顺序跑完整同一 80 条，使用同一 v3-evidence 裁判，不挑选重跑结果。

真实效果判据：逐题列出已知 5 条协议泄漏、循环内澄清、事实错误与超时在第二轮的结果；报告核心事实正确性、完整交付数、辅助评分、假成功数、已知 token 和时延变化。若第二轮退化，照实报告；不能用测试通过掩盖真实负结果，也不追加第三轮调参来选更好成绩。

第一轮所有有记录的运行都未触发压缩；autonomous 的循环次数最高 5、最高上下文比例约 0.142，guided 有记录的最高比例约 0.264（超时进程无最终状态，不据此推断其压缩次数）。当前数据不足以校准长上下文阈值，也不支持继续加大预算。因此预算与压缩参数保留原值，把“真实长上下文校准未覆盖”作为未完成的证据项，绝不随意回填数字。

评审限制：证据视图最多前 12 项、每字段 1800 字符；guided 的 `open004/010` 存在被引用但不在该视图内的已知证据。最终报告单独列出，不把裁判未见到的来源等同伪造。v1/v2 的接入与证据映射修订、额外成本、同 provider 并行评审可能造成的时延扰动也保留披露。单次重复不证明统计显著性或普适优越性。
