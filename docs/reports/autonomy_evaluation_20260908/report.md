# ISE guided / autonomous 两轮真实评测报告

日期：2026-09-08；任务一交付。两轮各 80 条真实运行和 80 条统一模型辅助评审全部完成，无缺失计划条目。

结论：本次修改后的 autonomous 在这组开放题中更有交付价值：完整交付 **13→18/20**，辅助分 **61.88→84.38**，但已知 token 消耗为首轮 **1.82 倍**。第二轮 guided 为 **14/20、68.75 分**；事实核心正确性却是 guided **20/20**、autonomous **19/20**。因此保留此次协议/用量/澄清修复，**不切换默认模式、不宣称 autonomous 全面更强或正式安全性通过**。

本次完成的是用户授权的“两轮真实评测—一次修改—复测—报告”，不是为原 OpenSpec 的真人评审和长上下文验收补造通过记录。完整逐题数据见[质量、成本与问题附表](cases.md)。

## 1. 范围与证据等级

研究编号：`autonomy-20260908-measured`。第一轮完整运行、分析后只进行一组产品修改；第二轮使用相同 20 道事实题、20 道开放题，每题两模式各一次。每轮计划 80 条，完整计划、失败与未完成条目都保留，不选取较好重跑覆盖结果。第二轮将模式调度顺序反转。

真实执行通过生产 LangChain / LangGraph 编排器、当前配置的 OpenCode Go 服务、`deepseek-v4-flash` 请求模型与真实搜索。每次查询独立进程、checkpoint、审计目录和空上传目录，并发 2，600 秒节点边界软取消，660 秒停止该查询的独立进程组。

证据明确分层：

- **真实运行**：两轮查询和真实 provider 响应 usage；这不是 mock 跑分。
- **模型辅助评审**：`glm-5.2` 请求 ID、隐藏模式 / 轮次标签、固定 v3-evidence 评分；不是真人评审，也没有裁判独立联网逐条查证。
- **自动化测试**：pytest、OpenSpec 和确定性回归；通过不代表真实答案正确。
- **离线回放**：将真实第一轮输出交给新解析器、禁止网络；验证已知语法处理，不代替第二轮质量。
- **入口 smoke**：真实 CLI 入口函数与 Flask `test_client` 路由调用；配置隔离但不 mock 模型，后者不是监听端口部署验收。

完整口径见[冻结协议](protocol.md)、[评审修订记录](review_revision.md)、[运行参数与嵌套用量审计](runtime_audit.md)。特别注意：入口请求 4000 / 0.2 未转发到 loop，主模型对象实际默认配置是 **5000 / 0.7**；两轮共享此缺口，不能声称入口参数契约已生效。

第一轮不能支持“autonomous 全面更强”：开放题同为 13/20 完成交付，配对辅助分 4 胜 / 12 平 / 4 负，平均差 -0.625 分。autonomous 用量明显更低，但 5 条工具协议泄漏和 1 条只给计划均被误当成成功，部分低成本来自提前收尾。guided 有 15 条被评为完整但终态非成功（事实 6、开放 9），也不能用其低成功率直接推断答案无用。

## 3. 一次修改及其边界

修改前已固定[第一轮结论、修改计划与验证标准](r2_change_plan.md)，并存入带时间及 SHA-256 的 `r2-change-plan.json`。相对第一轮，产品只修改 `orchestrators/react_loop_graph.py`：

1. 兼容单 / 双竖线 DSML；有效请求仍经过已启用工具及参数 schema 验证，未知语法拒绝并反馈。
2. 普通候选、降级合成和 best-effort 输出阻止未执行工具协议泄漏；合成阶段不执行新工具请求。
3. 保留 shim 的 usage / response metadata，并用原始调用 usage 校准上下文预算，即使内容随后被归一化或拒绝。
4. 模型拥有澄清权时，将分析器歧义作为可能误报的提示交给模型，不由循环内 critic 抢先终止；guided 与 skill preflight 保持不变。

这不是将 autonomous 改回 guided：judge、语义 narration guard、强制合成仍按原模式设置。没有硬编码题集答案、修正 Google 特例，或调整预算、temperature、并发及截止时间。纯计划自收尾、错误来源导致的自信错误、guided 过度保守及嵌套调用统计遗漏仍属于保留风险。

自动化验证：产品复测前完整 pytest **542 passed**；补充报告附表测试后的交付回归为 **543 passed、10 条既有 Pydantic 弃用警告**。OpenSpec 严格检查 **21 passed**，`git diff --check` 干净。修复前固定的 10 项诊断中 7 失败 / 3 通过，修复后全部通过，并补充合成边界和元数据测试。

真实 CLI / Flask smoke 各进行一次主模型调用，应用 total token 分别为 **1,308 / 1,322**，均与独立 HTTP usage 完全相同。它们验证简单路径，不证明 search_recovery 等所有嵌套调用都已接入共享 timing。

离线回放使用实际第一轮答案、实际工具 schema、禁止网络：4 条有效单竖线 DSML 恢复出工具请求，1 条畸形 DSML 明确拒绝，多 JSON 工具片段不再作为答案输出。纯计划 `open017` 仍保留候选文本，未假装修复语义完成判定。

- 第一轮注册应用调用的 usage 完整率 **0/75**，第二轮 **75/75**；各轮另有 1 条无模型调用的确定性澄清和 4 条硬超时，不混入该分母。但第二轮 `open009-guided` 和 `open010-guided` 仍有嵌套漏记，总差 **17,310 token / 3 次调用**。应用捕获率改善不等于全链路账务闭合。

费用分账：主评测两轮已知 **942,675 + 1,734,821 = ≥2,677,496 token**；最终 v3 辅助评审 **283,995 token / 152 次调用**，8 个无答硬超时由固定零分规则判定，不额外调用裁判；废弃 v1/v2 评审已知 **94,947 token**，另有停止时在途用量未知；真实入口 smoke **2,630 token**。启动检查另存、不混入主比较。没有账单/价格绑定，**USD 未知**。

## 5. 预算与验收边界

第一轮 75 条、第二轮 75 条具有最终 loop 记录的运行均未压缩。首轮 autonomous 最多 5 轮、最高上下文比例约 0.142；次轮最多 3 轮、比例约 0.131。guided 最高比例首轮约 0.264、次轮约 0.301；每轮 4 个被停止进程的最终状态未知。该题集不足以校准长上下文压缩参数，因此保留默认预算和阈值，不凭空回填数字。

预算决策：**不扩大预算，也不凭这组短上下文样本缩小压缩阈值**。不少失败已消耗大量调用，单纯加预算没有支持证据；autonomous 的低轮数又部分受提前收尾影响，不能据此证明将最大轮数降至 3 就足够。默认仍为 guided；愿意接受人工复核的开放任务可显式选 autonomous，但不能把它视为可靠的无人值守终态判断。

原 OpenSpec 状态：8.4 已实测但“不劣”未通过，保持未勾选；8.5 真实运行与模型辅助评分完成，**真人评分未进行**，保持未勾选；8.6 已给出保留参数的证据与决策，但长上下文校准未完成，保持未勾选；8.7 报告和 `docs/baseline.md` 登记完成。没有归档该 change。

限制：一次重复、有限题集、动态检索结果、模型别名可能变化、第一轮评审方法修订造成的额外并行负载，都限制了因果与统计结论。裁判只看到前 12 项证据及每字段 1800 字符；第一轮 2 条、第二轮 9 条答案引用了裁判视图外的有效 ledger 编号，其 grounding 分不能当作全资料核验。核心日期参考是在看正式答案前固定；其他开放题没有真人事实逐条签署。

下一步风险优先级（本次未追加实施）：先修入口生成参数转发与嵌套 usage 接线；再用独立题集验证计划误收尾、错误来源冲突处理和取消边界；长上下文压缩另设真实压力组，最后再决定默认模式或预算变化。这些不混入用户限定的第二轮修改。
